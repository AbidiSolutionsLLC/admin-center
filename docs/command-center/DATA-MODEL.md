# Command Center: data model

Collections the operator side owns or writes. Operators are not tenant members: their accounts, sessions and audit live in their own collections. Tenant-side models (`Company`, `User`, `App`, `AppAssignment`, ...) are in `../admin-center/DATA-MODEL.md`; identity models (`Identity`, `Session`, `OperatorSession`, `Invitation`, `SecurityEvent`, `oidc_operator_*`) in `../identity/DATA-MODEL.md`.

**Tenant key:** `company_id` where a model is per organisation (`OrganizationEntitlement`, `TenantNote`, `SeatUsage`, `TenantDailyStat`, `AttentionItem`). Platform documents (no tenant key): `OperatorAccount`, `OperatorAuditEvent`, `Plan`, `Announcement`, `Job`, `HealthCheck`, `HealthEvent`, `RouteMetric`.

**Ownership:** the Command Center writes entitlements, plans, notes, announcements and operator accounts; tenants never write them. Fields the Command Center writes on tenant models: `Company.status`, `is_active`, `plan`, `tags`, `trial_ends_at`, `last_activity_at` (touched at tenant sign-in, at most hourly).

|---|---|---|
| `OperatorAccount` (`server/src/models/OperatorAccount.model.ts`) | `email`, `full_name`, `password_hash`, `mfa.{enabled, secret_enc, verified_at, last_step}` (`last_step`: last accepted code step, a code is accepted once), `roles[]`, `status` (`active`/`suspended`/`invited`), `last_login_at`, `failed_attempts`, `locked_until`, `invited_by` | `secret_enc` encrypted with `ENCRYPTION_KEY` (`lib/cryptoService.ts`) |
| `OperatorAuditEvent` (`OperatorAuditEvent.model.ts`) | `operator_id`, `operator_email`, `action`, `target_type`, `target_id`, `company_id`, `details`, `category`, `before`, `after`, `reason`, `result`, `correlation_id`, `created_at` | Every operator write. When a company is involved, a tenant `AuditEvent` is also written with `source: 'operator'`, `module: 'operator'`, `actor_email: 'operator:<email>'` |
| `Plan` (`Plan.model.ts`) | `key`, `name`, `products[]`, `status` (`active`/`archived`), `description`, `seat_defaults`, `trial_days`, `version` | Default plans seeded by `seedProductRegistry` (`DEFAULT_PLANS`); edits raise `version` and reach tenants only on apply |
| `OrganizationEntitlement` | `company_id`, `product_key`, `status`, `seats_limit`, `source`, `plan_key`, `updated_by_operator_id` | Unique per (company, product) |
| `Company` | `status`, `is_active`, `plan`, `slug`, `tags`, `trial_ends_at`, `last_activity_at` | `last_activity_at` is touched at tenant sign-in, at most hourly |
| `Job` (`Job.model.ts`, runner `lib/jobs.ts`) | `type`, `payload`, `status` (`queued`/`running`/`done`/`failed`), `attempts`, `run_at`, `locked_until`, `last_error`, `finished_at` | Generic background work: atomic claim, handlers by type (`registerJobHandler`), retry after 1, 5, 30, 120 minutes (5 attempts), stale `running` rows reclaimed, finished rows removed after 30 days. First user: `plan.apply` |
| `HealthCheck`, `HealthEvent`, `RouteMetric` (`Health.model.ts`, `lib/health/*`) | check: `component` (unique), `state`, `detail`, `metrics`, `checked_at`; event: `component`, `from`, `to`, `detail`, `at` (TTL 7 days); metric: `instance`, `minute`, `count`, `errors_5xx`, `buckets`, `groups[{ group, count, errors_5xx }]` (TTL 24 h, counts only, never paths) | Platform health. A job every 60 s under the `health-checks` lease measures `admin_api` (route counters, 5 minutes), `database` (ping, primary), `identity` (signing keys per realm; optional `IDENTITY_KEY_ROTATE_BY`), `event_dispatcher` (lease age, orgs not acknowledged), `products_api` and `products_worker` (one probe of the products health route), `email`, `jobs`; each check has 5 s, a check that fails or times out is `unknown`. Thresholds: `lib/health/evaluate.ts` (DRD 7.1). `standalone_portals` is Phase 6 |
| `Announcement` (`Announcement.model.ts`, `operator/announcement.ts`) | `message` (≤ 280), `severity`, `starts_at`, `ends_at`, `created_by` | The current announcement is the latest started whose window contains now. Overview has an Announcement dialog (publish, replace, end) |
| `TenantDailyStat`, `AttentionItem` (`Signals.model.ts`, `lib/signals.ts`) | stat: `company_id`, `day` (UTC), `members_total`, `members_active`, `external_total` (0 until Phase 5), `sign_ins`, `seats` map, `admins_without_mfa` (unique per tenant and day, TTL 400 days); item: `kind`, `severity`, `company_id`, `summary`, `link`, `first_seen_at`, `last_seen_at`, `resolved_at`, `open`, `confirmed` (unique per kind and tenant while open) | Signals. Every 5 minutes under the `signals` lease each rule (DRD 4.4) is one query; matches are upserted, non-matches get `resolved_at`; a rule that throws leaves its own items alone. `sync_lag` is shown only after 10 minutes (`confirmed`). Every 6 hours under `tenant-daily-stats`, today's stat row per tenant is upserted from grouped queries. `provisioning_failed` = tenant in `provisioning` for over 15 minutes (the code has no such status) |
| `SeatUsage` (`SeatUsage.model.ts`, `lib/seats.ts`) | `company_id`, `product_key`, `used`, `computed_at` | Seats in use per tenant and product: members in an access state (onboarding, active, probation, on_leave), active, reached by an active assignment of the product's app, while the tenant is active and the entitlement is active. Recomputed (coalesced to once a second per tenant) after every `app_access.changed` emit commits; never on page load |
| `TenantNote` (`TenantNote.model.ts`) | `company_id`, `operator_id`, `operator_email`, `body` (≤ 2000), `created_at` | Internal operator notes; append-only |
| `IdentityProviderConnection` | `tenant_approval.{tenant_id, approved_at, operator_id}` | Written by approve-tenant |
| `oidc_operator_*` | oidc-provider storage | `../identity/DATA-MODEL.md` |

Operator actions recorded in the audit log: `org.provisioned`, `org.suspended`, `org.reactivated`, `org.closed`, `org.plan_assigned`, `entitlement.updated`, `identity_provider.tenant_approved`, `plan.created`, `plan.updated`, `operator.created`, `operator.updated`.

## Operator audit actions

Recorded in `OperatorAuditEvent`: `org.provisioned`, `org.suspended`, `org.reactivated`, `org.closed`, `org.updated`, `org.plan_assigned`, `org.note_added`, `org.note_deleted`, `entitlement.updated`, `entitlement.override_removed`, `identity_provider.tenant_approved`, `plan.created`, `plan.updated`, `onboarding.invite_resent`, `onboarding.first_admin_changed`, `announcement.set`, `announcement.ended`, `operator.invited`, `operator.invite_accepted`, `operator.created`, `operator.updated`, `operator.session_revoked`, `audit.exported`. Notes and `audit.exported` are not mirrored into the tenant audit log.

## Retention

`HealthEvent` TTL 7 days; `RouteMetric` TTL 24 hours; `TenantDailyStat` TTL 400 days; finished `Job` rows removed after 30 days; `OperatorAuditEvent` is kept (append-only).
