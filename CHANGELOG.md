# Changelog

Format: [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Each entry lists the change and its user-visible or deploy-visible effect. Commit details: `../docs/wrapup/CHANGE-LEDGER.md`.

## [Unreleased]: elevation, branch `feat/elevation`

### Changed
- 4.6: overrides. `PUT /operator/v1/orgs/:id/entitlements/:productKey` now requires `reason` (400 `REASON_REQUIRED`; existing callers must send one) and accepts `expires_at`; new `DELETE .../override` returns a product to plan state; the entitlement stores `reason` and `expires_at`. An hourly job under a lease (`lib/overrideJobs.ts`, DRD says daily) removes active overrides whose date has passed, audited with actor `system` (`OperatorAuditEvent.operator_id` is now optional; `operator_email` is `system`). Stored `source` stays `operator`. The Products tab of the tenant page gets Override, Remove override and Change plan (with a dry-run preview); the list's Entitlements button opens that tab and the old entitlements dialog is gone.
- 4.5: plans. `Plan` gains `description`, `seat_defaults`, `trial_days` and `version` (raised on every edit); `OrganizationEntitlement` gains `plan_version` and the status `restricted` (not active, so access is off and data is kept; the Platform API and `entitlement.changed` may now carry it, and the event gains optional `source` and `seats_limit`). New `operator/plans.ts` holds the plan routes, `applyPlanToOrg` (also used by `PATCH /orgs/:id`, with `?dry_run=true`) and `ensureDefaultAccess` / `bumpOrgAuthz` (moved unchanged from `routes.ts`). Behaviour change: an operator override is no longer re-labelled as plan-sourced when a plan is applied, and plan-sourced entitlements for products that left the plan become `restricted`. New `POST /operator/v1/plans/:key/apply` queues one job per tenant. New generic job runner (`lib/jobs.ts`, `Job` model, started in `index.ts`). A tenant created on a plan gets `trial_ends_at` from `trial_days`, `plan_version` and the seat default on its entitlements. `audit()` moved into `operator/audit.ts` (`writeAudit`) so a job can write as the operator who started it. Plans page: description, default seats, trial days, tenant count, version, Apply to organizations with a preview.
- 4.4: tenant profile. New `operator/tenants.ts` (`GET /orgs/:id/products`, `/admins`, notes list/add/delete) and a `TenantNote` model; `PATCH /orgs/:id` also sets `tags` and `trial_ends_at` (plan change unchanged; `plan_key` is now optional). The `audit()` helper takes `mirror: false` so internal notes stay out of the tenant's audit log. New page `/operator/organizations/:id` on `ObjectPage` with Summary (tags, trial, identity providers with the Entra tenant approval button), Products, Onboarding (stage, resend, change first admin), Admins, Activity (the org's audit entries) and Notes tabs; the Organizations list opens it on row click.
- 4.3: tenant directory. `Company` gains `tags` (max 10, each at most 30 characters), `trial_ends_at`, `last_activity_at` and the DRD 3.1 indexes. `last_activity_at` is set at sign-in (`recordLoginSuccess`), at most once per hour per tenant, by one conditional write. `GET /operator/v1/orgs` filters by `plan`, `tag`, `trial` and sorts by `created|name|members|last_activity`; the per-page `$max(last_login)` aggregation is gone and the member counts (total and active) come from one grouped aggregation. Tenants already in the database show no last activity until their next sign-in. Organizations page rebuilt on `ListPage` (URL-held filters, sort, status badge, tags, trial end).
- 4.2: operator audit. `OperatorAuditEvent` gains `category` (derived from the action prefix unless named), `before`, `after`, `reason`, `result` and the DRD 4.1 indexes; the `audit()` helper stores them (they were being dropped, F6) and redacts secret-looking keys. `GET /operator/v1/audit` filters by `operator_id`, `category`, `from`, `to`; new `GET /operator/v1/audit/export` (CSV stream, 50,000-row cap, audited). Audit page: category, operator and date filters, Before/After/Reason in the drawer, Export CSV for operators with `audit.export`. Rows written before this change have no stored category: the API derives it from the action for display, but the category filter only matches new rows.
- 4.1: operator roles. `operator/permissions.ts` holds the DRD 4.5 map (`platform_admin`, `operations`, `support`, `auditor`) and `requirePermission(perm)`; every `/operator/v1` route has one, `GET /operator/v1/me` returns the operator and permission list. `findOperatorAccount` and the hosted sign-in accept any of the four roles (F7); `POST`/`PATCH /operators` accept them in `roles`. The console navigation and the Organizations, Plans and Operators buttons follow `/me`. `products.write` is not defined (Phase 6). Existing `platform_admin` accounts keep full access.
- 3.8: browser-test setup for the Admin client: `client/playwright.config.ts`, `npm run test:e2e`, sign-in helpers for the tenant and operator realms (`client/e2e/helpers/auth.ts`, mocks the identity provider and runs the app's real PKCE flow) and specs for the two reference pages (`operator-plans.spec.ts`, `operator-audit.spec.ts`). `@playwright/test` was already a devDependency, so no dependency was added. Specs are typechecked (`tsconfig.node.json` now includes `e2e`) but not run until Phase 7.
- 3.7: `DESIGN.md` records the Phase 3 tokens, components, shell and templates, and the migrated-page checklist. The products design documents are untouched (decision S-11).
- 3.6: reference pages for the owner's review: `OperatorPlansPage` on `ListPage` (table, tags, create/edit dialog with `FormField`) and `OperatorAuditPage` on `ListPage` + `Drawer` (action filter and open entry live in the URL: `?action=`, `?entry=`; cursor paging; sticky header). Same API calls and hooks as before; the audit action filter was already supported by `GET /operator/v1/audit?action=` (exact match).
- 3.5: three page templates in `client/src/components/templates/`: `ListPage` (PageHeader, Toolbar, table, Drawer), `ObjectPage` (PageHeader, KeyFacts, URL-synced Tabs), `DashboardPage` (PageHeader, StatTile row, 12-column grid); `PageStates` gives all of them the loading, error, empty and no-access states.
- 3.4: one `AppShell` (rail 248/64 px, 56 px top bar, content max 1280 px) with two configs in `components/layout/navigation.ts`: `admin` and `operator` (red "Operator" marker from the `error` token, no launcher or notifications). Items are filtered by a permission list and role passed in (same rules as the old sidebar). `TenantShell` / `OperatorShell` in `shells.tsx` replace `AdminShell`, the inline-styled `Sidebar` and `OperatorLayout` (all deleted); `TopBar` became `TenantTopActions`. Rail collapse state is in `useUIStore`. Routes and navigation entries are unchanged.
- 3.3: `DataTable` gains `stickyHeader`, cursor `paging` and keyboard rows (Tab, Enter/Space, Up/Down); `ConfirmDialog` gains `requireText` (typed confirmation) and `reasonField` (`onConfirm(reason?)`); `StatusBadge` is now dot + word, the filled pill only for the new `action-needed` variant (all ten existing callers change look); new `FormField` (label, hint, error, required), `Textarea`, `Select`. All new props are optional. `Combobox` and `DatePicker` (DRD 9.2) are not built: no screen needs them yet.
- 3.2: new shared components in `client/src/components/ui/`: `PageHeader`, `Toolbar` (+`FilterChip`), `StatTile`, `KeyFacts`, `Tabs` (URL-synced, on `@radix-ui/react-tabs`), `Drawer` (on `@radix-ui/react-dialog`), `HealthPill`, `Timeline`, `SectionBoundary`, `CopyField`, `Tag`, `SeatMeter`; hook `hooks/useUrlParam.ts` keeps filter/tab state in the URL. No new dependency, no page uses them yet.
- 3.1: design tokens for the shared kit (DRD 9.1): type scale (`text-label/table/body/section/title/tile`), `max-w-content`, rail and top-bar sizes, row heights, `duration-fast/panel`, `rounded-control/card`; `.tabular` utility; reduced-motion rule. No new colours. Mirrored in `constants/theme.ts`.
- 2.7: two scheduled jobs (`lib/invitationJobs.ts`, via `periodic.every`): an invitation reminder every 30 minutes (one reminder e-mail, template `invite_reminder`, for a pending invitation expiring in 23 to 24 hours; carries no link because the raw token is never stored) and a nightly delete of accepted, revoked and superseded invitations 180 days after their last change.
- 2.6: operator onboarding API (`GET /orgs/:id/onboarding`, `POST /orgs/:id/onboarding/resend-invite`, `PATCH /orgs/:id/onboarding/first-admin`, `GET /onboarding`) in `operator/onboarding.ts`. The first admin is now found through `UserRole` + the Super Admin role (`findFirstAdmin`), not the legacy `User.role`.
- 2.5: `POST /operator/v1/orgs` provisions in one transaction (company, roles, security policy, entitlements, first admin, invitation, welcome e-mail row, events). A failure leaves nothing behind; the cleanup block is gone. `seedSystemRoles`, `seedSecurityPolicy` and `seedDatabase` take an optional session; `EmailMeta` takes an optional `session` so the outbox row joins the caller's transaction. `invite_email_sent` now means "accepted for delivery" and is always true on a 201.
- 2.4: member detail shows an Invitation panel for invited members (state, last sent, expiry, e-mail delivery status and last error) with Resend, Copy link (new link, no e-mail, shown once, audited) and Revoke. New `GET /people/:id/invitation`, `POST /people/:id/invitation/revoke`; `resend-invite` accepts `?copy=true`.
- 2.3: the activation page verifies the link on load and shows the form, or an expired / superseded / already-used / revoked / not-valid notice with its action (`Send me a new link`, `Sign in`); the e-mail field is read-only. Forgot and reset password use the same `AuthNotice`.
- 2.2: `POST /people/verify-invite` answers six outcomes with codes (`INVITE_EXPIRED`, `INVITE_SUPERSEDED`, `INVITE_ALREADY_USED`, `INVITE_REVOKED`, `INVITE_NOT_FOUND`); new public `POST /people/renew-invite` (always 202, 3 per invitation per day); `POST /auth/setup-password` runs in one transaction with an atomic consume, `email` is optional, and a reused or expired link now answers the same codes instead of `INVALID_TOKEN` (400).
- 2.1: `InviteToken` becomes `Invitation` (kind, state, no TTL index) and every invitation is made by `lib/invitations.ts`; a new invitation supersedes the user's pending one. The `invite_tokens` collection is not migrated (fresh start); `lib/lifecycleAutomations.ts` (dead code with a placeholder link) is removed.

## [Unreleased]: wrap-up clean-up (2026-11-13), branch `chore/wrapup`

### Added
- QR code on the MFA enrolment page, with a copy button for the setup key.
- `AuthLayout` for the signed-out pages (login, onboarding, forgot and reset password).
- `npm run typecheck` in server and client.
- Repository docs: `README.md`, `AGENTS.md`, `DESIGN.md`, `docs/ARCHITECTURE.md`, `docs/CONFIGURATION.md`, `docs/portals/*`.

### Changed
- Hosted sign-in pages use the Karbexa brand and are skinned per app: Products light, Admin dark with an "Admin" badge, Operator dark with a red "Operator" badge.
- Brand amber is `#f59e0b` (was `#f5b02a`), matching the products app.
- Package names `@karbexa/admin-api` and `@karbexa/admin-web`. Node 22 LTS baseline (`engines`, `.nvmrc`, `@types/node` 22).
- **Product launcher URLs** default to `PRODUCTS_SPA_ORIGIN` + the product page (for example `/people/home`). Existing databases update on the next `npm run seed:products`.
- `npm run seed:first` requires `SEED_ADMIN_PASSWORD`; it no longer has a built-in default password.
- `server/.env.example` lists every optional variable the code reads; the broken key-format comment is repaired; unused `SENDGRID_API_KEY` removed.

### Fixed
- `GET /api/v1/work-schedules/assignments` was unreachable (captured by `/:id`).
- `DELETE /api/v1/holidays/assignments/bulk` was unreachable (captured by `/assignments/:id`).

### Removed
- One-off scripts at the server and client roots; root `scripts/seed-e11.ts` forwarder. Untracked: `client/.env`, `*.tsbuildinfo`, `.omc/`.
- Old planning documents moved to `docs/archive/` (they were previously not in git at all).
